The core prompt is less than half as long. It keeps what every reply needs: how to reply, how to work, and one line for each call. The details of the tree of reflexes (every setting of a node) and of units (waits, what the model is told and in what order, units of its own, who has the environment) are in two pages that a program reads on demand, `guide("tree")` and `guide("units")`. A page that was read is given again after a summary of the conversation. `reflex_method()` still works and returns `guide("tree")`. The other sections are brought to the same standard. The request for a reflection after an episode (every embodiment but a robot, whose request is unchanged) asks for a note, a memory entry or a skill and no longer for a reactive helper: the nodes of a tree are kept from the tree the agent set. The library section gives `setup` in the signature of `library.propose` and no longer names a `tree` call. The checklist section has no example task. The section on world memory, which no setting could switch on and whose calls do not exist, is removed. The core names no kind of environment any more. Its default configuration has no table for a computer or a game and no table of prompts: a kind's package says its prompt and the agent's settings on it in its `kinds.toml` (`prompt`, `agent`), and may declare what is particular to the kind (`unnamed_in_lock`, `library_experience`, `record_waits`, `memory_report`, `interfaces`). Where nothing names a kind, it is `none`, a conversation with no environment, not a robot. What breaks: a `skill.toml` must say `embodiments` (the kinds it runs on, or `["*"]`); an embodiment file and a worker's profile must name their `kind`; `harness.embodiments.profile()` is gone (it built one kind's worker profile and is that kind's package's). `verify(claim)` is a call of every kind.

核心提示词缩短到不到原来的一半，只留每次回复都用得上的内容：怎么回复、怎么工作、每个调用一行。反射树的细节（节点的每一项设置）和单元的细节（等待、会被告知什么及顺序、自己启动的单元、谁占用环境）放进两页按需读的说明里：`guide("tree")` 和 `guide("units")`。读过的页在对话被摘要之后会重新给一遍。`reflex_method()` 仍然可用，返回的就是 `guide("tree")`。其余几段按同一标准整理：一轮结束后的复盘请求（机器人以外的环境；机器人的请求不变）只要笔记、记忆或技能，不再要“反应式辅助”，反射树的节点从 agent 设好的树里保留；学习库那一段在 `library.propose` 的签名里补上了 `setup`，不再提并不存在的 `tree` 调用；清单那一段不再带具体任务的例子；讲世界记忆的那一段没有任何设置能打开，提到的调用也不存在，已删除。核心不再点名任何一种环境。默认配置里没有电脑或游戏的专用段落，也没有提示词对照表：每种环境的包在自己的 `kinds.toml` 里声明它的提示词包和 agent 在它上面的设置（`prompt`、`agent`），也可以声明这种环境特有的东西（`unnamed_in_lock`、`library_experience`、`record_waits`、`memory_report`、`interfaces`）。没有指明环境种类时，默认是 `none`（没有环境的对话），不再是机器人。会受影响的：`skill.toml` 必须写 `embodiments`（它运行在哪些种类上，或 `["*"]`）；环境文件和 worker 的 profile 必须写明 `kind`；`harness.embodiments.profile()` 已删除（它只为一种环境构造 profile，应当放在那种环境的包里）。`verify(claim)` 现在每种环境都有。

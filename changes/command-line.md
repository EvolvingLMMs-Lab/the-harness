The command line takes the forms people know from other agents. `harness "first message"` opens the chat with that message; `harness -p "question"` answers and exits, with what is piped in (`--output-format text|json|stream-json`); `-c` goes on with the most recent chat and `-r [CHAT]` with one by id or title; `-v` prints the version. A mistyped command gets "Did you mean harness update?" and exit status 2 instead of starting anything. `harness --help` is one short screen, the daily commands first, and each command a package adds has a line of its own (a package's `commands.toml`). New: `harness status` (version, model, identity, session host, what is connected), `harness config show|get|set|unset|edit|path` (settings by `section.key`; `--identity ID` for an identity's own value; a provider's key by its variable's name), `harness logs [NAME] [-n N] [-f]`, `harness host status|start|stop|restart` and `harness host --help`, `harness completion bash|zsh|fish`, and `harness sessions` for an identity's chats (list, rename, archive, delete). `harness doctor` lists Python, the model with its key or sign-in, whether the session host starts, the packages that were left out and which `harness` the terminal runs, each with its fix; the deploy and GPU lines appear only where a deploy places services. What changes: `harness config EXPERIMENT` is still the eval package's but `harness config` with `show`, `get`, `set`, `unset`, `edit` or `path` (or alone) is the settings; `harness status` alone is the new status, with service names or `--deploy` the local-models package's; `harness -c`/`-r` open the identity's chats when the agent package is installed. Also for the app's page: a chat's own model and effort, files attached to a message (`/api/agent/attach`, `say` with `files`), the log over the API (`/api/app/log`), a failed turn's record with its fix and code, and a reply's record with what the model thought.

命令行改成了大家在别的 agent 里用惯的写法。`harness "第一句话"` 带着这句话进对话；`harness -p "问题"` 答完就退，管道送进来的内容一起交给它（`--output-format text|json|stream-json`）；`-c` 接着最近的对话，`-r [对话]` 按 id 或标题接着某个对话；`-v` 打印版本。命令打错时得到“Did you mean harness update?”和退出码 2，不会启动任何东西。`harness --help` 只有一屏，日常命令在前，扩展包加的每条命令各有一行说明（包里的 `commands.toml`）。新增：`harness status`（版本、模型、身份、后台服务、接入的东西）、`harness config show|get|set|unset|edit|path`（设置按 `段.键` 读写；`--identity ID` 读写身份自己的值；提供商的 key 用它的变量名）、`harness logs [名字] [-n N] [-f]`、`harness host status|start|stop|restart` 和 `harness host --help`、`harness completion bash|zsh|fish`，以及用 `harness sessions` 管身份的对话（列出、改名、归档、删除）。`harness doctor` 逐项列出 Python、模型及其 key 或登录状态、后台服务能否启动、被跳过的扩展包、终端里的 `harness` 是哪一个，每项带修法；只有 deploy 真的放置了服务时才显示 deploy 和 GPU。有变化的地方：`harness config 实验名` 仍然是 eval 包的，但 `harness config` 后面跟 `show`、`get`、`set`、`unset`、`edit`、`path`（或什么都不跟）是设置；单独的 `harness status` 是新的状态，带服务名或 `--deploy` 时是 local-models 包的；装了 agent 包时 `harness -c`/`-r` 打开的是身份的对话。另外为 app 的页面增加：单个对话自己的模型和推理强度、随消息发送的附件（`/api/agent/attach`、`say` 的 `files`）、通过 API 读日志（`/api/app/log`）、失败回合的记录带修法和代码、回复的记录带模型的思考内容。

A kept tree (`reactive` entry) may call `situations(...)` beside `set_reflex(...)`, so the list comes back with the nodes; a line its `covers=` names that the list does not have is left out when it is loaded. The refusal of a kept tree that calls something else names the line and the call, and the library's page states the rule with an example.
<!-- zh -->
存进库的树（`reactive` 条目）除了 `set_reflex(...)` 还可以调用 `situations(...)`，这样清单会和节点一起恢复；加载时 `covers=` 里指向清单中不存在的行会被略过。存进库的树调用了别的东西时，拒绝里写明是哪一行的哪个调用，库的说明页写出了这条规则并给了例子。

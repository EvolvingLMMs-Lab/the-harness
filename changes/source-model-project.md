A model's source, the model and its reasoning effort are three separate things everywhere. Choosing a source (Claude Code, Codex, a provider's key) keeps one of its models by the model's own name, an agent's being the one the agent is set to, instead of showing the source as the model; every other model the source offers is one choice away (**More models of …** in the app, `/model` in the terminal chat, and the first run asks which model of an agent to use). The effort's choices are the levels the model in use has, in the app's composer, in Settings › Model and with `/effort`. A chat you start can be opened on a project, as a session of Claude Code or Codex is: the composer's new "where" menu lists your projects, **Open folder…**, and for a git project an isolated copy (a git worktree on the chat's own branch); the chat's work is done there, and the chat list groups chats by project (`/project` in the terminal chat, `harness agent chats new TITLE --in FOLDER [--worktree]`, `harness agent chats place`, `Agent.new_chat(folder=...)`). Gemini CLI, Grok and the other agents of the ACP Registry need no command line of theirs installed first: choosing one installs its adapter, and one that is not signed in is signed in to through the ways it offers (buttons under the failure in the app, a question in the terminal, `harness agents login NAME`). An API model's reasoning effort has the levels its provider's API tells apart, also for a provider's own endpoint. The settings page's way back is at the foot of its left bar, where the Settings entry is. The edges between the parts of the app's window can be dragged (the chat list, the tools panel, the Settings page's list, the calendar's left column): the window remembers the widths, and a double-click on an edge puts it back.

模型的来源、模型本身和思考强度在各处都是分开的三样东西。选一个来源（Claude Code、Codex、某个提供商的 key）时，保存的是它的某个模型，用模型自己的名字，agent 来源保存的是它自己当前设的那个，不再把来源当成模型显示；来源提供的其它模型都只差一步（app 里的 **某来源的其它模型…**，终端聊天里的 `/model`，首次引导在选了 agent 之后会问用它的哪个模型）。思考强度的选项是当前模型有的档位，app 的输入框旁、设置 › 模型 和 `/effort` 都是这样。你自己开的对话可以开在一个项目上，就像 Claude Code 或 Codex 的一次会话：输入框旁新的“在哪里做”菜单列出你的项目、**打开文件夹…**，git 项目还可以选隔离副本（对话自己分支上的 git worktree）；对话的事就在那里做，对话列表按项目分组（终端聊天里的 `/project`、`harness agent chats new 标题 --in 文件夹 [--worktree]`、`harness agent chats place`、`Agent.new_chat(folder=...)`）。Gemini CLI、Grok 和 ACP Registry 里的其它 agent 不用先装它们的命令行：选中后自动装好适配器，没登录的用它自己提供的方式登录（app 里是报错下面的按钮，终端里是一个问题，命令行是 `harness agents login 名字`）。用 API 的模型，思考强度有提供商的 API 能区分的那几档，直连提供商时也一样。设置页的“返回”在它左栏的最下面，就是“设置”入口所在的位置。app 窗口各部分之间的边可以拖动（对话列表、工具面板、设置页的列表、日历的左栏）：窗口会记住宽度，双击边恢复原样。

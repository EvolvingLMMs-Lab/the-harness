The core prompt says how to divide work: the plan becomes goals in order, each with a
result that can be checked, divided where the model has to decide and not by size; what
has worked becomes part of a larger program. While a program runs the model first follows
it and then prepares what comes after. A problem of the same kind that comes back is
answered by listing its possible causes and changing the approach. A node of the tree that
acts at the wrong moment is changed in the tree (the core, the pages on the tree and on
units say so), and `at_priority` is described as what it is: one action, during which every
lower node waits. The page on the library now says how to learn what the library does not
hold and what counts as learned; the instruction of an active learning run keeps only what
is particular to that run.

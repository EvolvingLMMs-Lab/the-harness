A conversation goes on until you end it. The agent's answer, a reply in plain text, ends its turn, not the conversation: the next message goes to the same conversation, which keeps its messages, the variables of its programs, its rules, its facts and the environment. What the agent left running goes on after the answer, and the end of a unit or an event starts its next turn without a message. Model calls and time are limits of a turn and begin anew with the next one; a turn that reaches one, fails or is cancelled (`/cancel`) ends with that reason and the conversation waits; cost is counted for the whole conversation. Every turn ends with a `turn_result` record. `/clear` is another name of `/new`. Sessions are kept on disk as they go (`conversation.json` beside the trace), and one that ended is continued in its own session id with a new kernel: `harness --continue`, `harness --resume ID`, `harness run --continue | --session ID "task"`, `harness sessions resume ID`, `/resume`, `Host.resume_session()`; what lived in the old process (variables, rules, running programs) is gone, and the agent is told so. A sub-agent whose turn ended can be sent another message (`send_agent`) and goes on with its history. A conversation whose workspace is needed by another is parked, and its next message continues it. A run nobody talks to keeps its conversation as well: `harness program CONFIG --continue EPISODE --message "..."` gives the episode in that directory one more turn, in its own session, against the worker that runs.

What breaks: the prompt no longer teaches `<finish>`; `<finish>` and `finish()` are still accepted and mean the same as a text answer. In a run without a user (a benchmark), a reply in plain text now ends the run as its answer instead of being sent back as a format error. A frontend that waited for `FINISHED` after an answer waits for the `turn_result` record instead (the state after it is `IDLE`, whose `reason` is how the turn ended); `harness run "task"` and the MCP server's `run_task` still end the session they started after its turn. A sub-agent's report has no `question` and no `asks` status: what it asks is its answer. ACP `session/cancel` ends the turn and keeps the conversation. A task the agent package gives (`harness agent`) ends with its turn, so a question it asks comes back as the task's answer. In `summary.json`, a conversation closed between turns keeps the status of its last turn; `closed` is a turn that was cut short. The evaluator's outcome is read when the conversation ends, as before, since a worker evaluates once. A kernel that dies ends the conversation; it is continued with `--resume`. Esc in the terminal chat still pauses.

对话会一直继续，直到你结束它。agent 的回答（一条纯文本回复）结束的是它的这一轮，不是对话：下一条消息发给同一个对话，它保留自己的消息、程序的变量、规则、facts 和环境。agent 留下仍在运行的东西在回答之后继续运行，某个单元结束或有事件到达时，不需要消息就开始它的下一轮。模型调用次数和时间是一轮的上限，随下一轮重新开始；达到上限、出错或被取消（`/cancel`）的一轮带着这个原因结束，对话继续等待；费用按整个对话统计。每一轮以一条 `turn_result` 记录结束。`/clear` 是 `/new` 的另一个名字。session 随进行随时写到磁盘上（trace 旁边的 `conversation.json`），已经结束的 session 用一个新的 kernel 在它自己的 session id 里继续：`harness --continue`、`harness --resume ID`、`harness run --continue | --session ID "task"`、`harness sessions resume ID`、`/resume`、`Host.resume_session()`；旧进程里的东西（变量、规则、正在运行的程序）没有了，agent 会被告知。一轮结束的子 agent 可以再收到消息（`send_agent`），并带着它的历史继续。工作区被别的对话需要的对话会被暂存，它的下一条消息让它继续。没有用户的运行同样保留它的对话：`harness program CONFIG --continue EPISODE --message "..."` 让该目录里的 episode 在它自己的 session 里、对着正在运行的 worker 再走一轮。

不再兼容的部分：提示词不再教 `<finish>`；`<finish>` 和 `finish()` 仍被接受，含义与纯文本回答相同。在没有用户的运行（benchmark）里，纯文本回复现在作为回答结束这次运行，不再被当作格式错误退回。原来在回答之后等待 `FINISHED` 的前端，改为等待 `turn_result` 记录（之后的状态是 `IDLE`，它的 `reason` 说明这一轮怎样结束）；`harness run "task"` 和 MCP server 的 `run_task` 仍然在这一轮之后结束它们启动的 session。子 agent 的报告不再有 `question`，也没有 `asks` 状态：它问的问题就是它的回答。ACP 的 `session/cancel` 结束这一轮并保留对话。agent package（`harness agent`）交出的任务随它的这一轮结束，所以它提的问题会作为任务的回答返回。在 `summary.json` 里，在两轮之间被关闭的对话保留最后一轮的状态；`closed` 表示一轮被中途打断。评测结果仍在对话结束时读取，因为 worker 只评一次。kernel 死掉会结束对话；用 `--resume` 继续它。终端对话里的 Esc 仍然是暂停。

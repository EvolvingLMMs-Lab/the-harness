大多数语言模型 agent 一步一步地行动：观察，选一个动作或工具调用，再观察。模型就在控制回路里，所以每一步都要等它，每一步都要花一次调用。

**Agentic control** 把模型从这个回路里拿出来。模型改为编写控制器：会感知、会行动、会检查自己结果的程序，交给学习型策略的任务，以及每个控制步都运行的反应规则。控制器自己运行，模型只在**决策点**被再次调用：任务开始时，你说话时，一个程序结束时，或者发生了正在运行的代码处理不了的事。已经编程的阶段不需要继续调用模型；需要新的语义决策时，任务再回到模型。

## 一个任务怎样运行

| 部分 | 运行时机 | 做什么 |
|---|---|---|
| 模型 | 在决策点，以秒计 | 读发生了什么，思考，写下一个程序，回答你 |
| 程序和 skill | 程序运行期间 | 模型写的 Python 调用 skill（`click`、`read_page`、一个学习型策略）；每次调用作为一次有界执行运行，以一个事件结束：`COMPLETED`，或让它停下的原因 |
| 反应规则 | tick 的每个周期 | guard、反射和事件 handler：不经模型就停下一次执行、行动或发出事件的小函数 |
| tick | 控制周期或离散操作边界 | 调度有界执行与中断；连续环境采样并合并命令，离散环境按真实时间截止条件等待结果 |
| worker | 每条命令 | 运行环境；它的 shield 放行或拒绝每条命令，不管命令是谁写的 |

正在运行的代码处理不了的事，作为**事件**往上交：guard 触发时，以一个程序可以处理的事件结束它的执行；程序结束，或者放过一个事件时，模型在下一个决策点才去看。

多个执行可以同时运行。环境有 **channel** 时（游戏的按键、按钮和指针），每个执行在自己命令用到的 channel 上推进，由 tick 合并；去抢另一个执行占着的 channel 会得到一个冲突事件。没有 channel 时，它们轮流运行。

机器人、桌面和游戏的 learned policy 共用 `run_policy` 的执行生命周期。模型适配负责观测格式和动作解码，将结果交给对应 embodiment 的原生执行器；tick、输入占用、保护与执行回执沿用现有链路。起始关节姿态、夹爪等条件属于机器人适配，不是公共 policy 契约。原生 HTTP 协议与包自定义适配的接法见 [learned-policies 包](https://harness.lmms-lab.com/packages/learned-policies/)。

## 控制程序与任务环境

运行控制程序的 Python 解释器，与程序实际作用的环境分开。项目工作区拥有目标文件、工具链和进程；在控制程序里 import 模块，不等于测试刚修改的目标模块。控制程序通过 worker 读取和修改文件，用项目实际使用的解释器运行命令，再检查真实结果。

Minecraft 这类连续环境按控制频率推进。项目工作区执行离散操作：启动进程后返回待完成的回执，由现有调度器观察完成情况，同时保留 guard 和取消能力。轮询不会推进目标的逻辑步数，也不会伪造截图。模型仍然编写完整阶段的程序，只在决策点回来；没有另一套 coding agent 或任务规划器。

操作数据返回给调用程序；完成与中断事件仍经过 handler，并持续写入轨迹。不可变目标证据保存在运行产物中。下一次模型决策收到有界程序输出、事件计数和未处理事件，不会因程序读取了大量内容而再次收到所有全文。

每条命令都有截止时间。会话拥有进程，在声明的输出上限内保留原始输出，并给模型有界的预览，并报告实际观察到的退出或取消结果。命令退出码、模型宣布完成、独立验证的任务结果，是三个不同事实。首个项目后端是拥有当前 OS 用户权限的本地执行；绑定目录不等于给 shell 建立沙箱。[运行项目任务](/docs/zh-cn/use/projects/)

## 边做边想

长程序运行期间，模型可以提前准备一次后续决策。程序结束时，只有结果满足模型写下的条件、相关输入也依然有效，这个答复才会生效。需要模型判断的上报和用户的新消息会触发新的决策。独立的程序和规则可以继续运行。时间线上能看到模型调用和程序的重叠。 [观看与回放](/docs/zh-cn/use/replay/)

## 你始终在回路里

无论 agent 在做什么，你的消息都会立刻到达模型：它决定正在运行的程序是跑完、在新动作旁边继续跑，还是停下。你可以暂停它，逐个审批程序，或者接手电脑再交还；你一碰鼠标或键盘它就让开，识别出的敏感步骤（凭据、付款、发送、删除、无法撤销的操作）会被拦截，支持一次性授权的工作区会请你确认（[中途插话和接手](/docs/zh-cn/use/interrupt/)）。

## In-context learning

模型的权重从不改变。agent 学到的东西进入一个它会读、会运行的 **library**：写进 prompt 的笔记、记忆、带测试的 skill、反应规则。一条条目只有自己的测试通过才会被收入，并且在同一次运行里就生效。agent 可以在任务开始前先学会一个环境（[让它学会一个环境](/docs/zh-cn/learn/learn-an-environment/)），工作时也在继续学（[边做边学](/docs/zh-cn/learn/while-working/)）。

## 任意模型，任何能行动的东西

- **任意模型**：通过 OpenRouter、OpenAI、Anthropic 等 provider 使用托管模型，或者你自己运行的模型（[模型和 provider](/docs/zh-cn/configure/models/)）。
- **任何能行动的东西**：The Harness 只通过观测和命令接触一个环境。你的桌面、浏览器、游戏、机器人，各自是一个包，带着自己的 worker、skill 和 prompt，在任务第一次需要时自动安装（[包](/docs/zh-cn/configure/packages/)）。
- **工具和知识**：MCP 服务器给 agent 提供工具，Agent Skills 提供说明（[接入 MCP 服务器和 Agent Skills](/docs/zh-cn/extend/mcp/)）。
- **结果写明是什么产生了它**：每次运行都把 prompt、skill、模型、包和决定计算结果的每一项设置记成一个 identity（[配置](/docs/zh-cn/configure/configuration/)）。

## 任务与持续性 Agent

Harness 本身能够独立完成有界的自然语言任务：模型编写控制程序，在决策点接收结果，
继续执行直到任务结束。CLI 任务和 benchmark episode 使用同一个运行时，不依赖可选的
agent package。任务内的上下文和世界状态属于当前 run，不代表持续身份。完成或预算耗尽
会结束任务；任务中的澄清和纠正不会重置预算，也不会自动开始下一轮对话。

可选的 agent 管理持续身份、多轮对话和长期记忆，将明确目标与上下文交给 Harness，
再处理任务结果。学习仍属于任务引擎：显式绑定的 library 可以冻结或更新，经过验证的
skill 和 reactive rule 可以在本次运行中激活。学习库不是个人记忆库，不要求存在 agent 身份。

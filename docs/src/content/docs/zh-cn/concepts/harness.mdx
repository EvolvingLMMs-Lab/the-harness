我们不必在每个动作之前都停下来思考。走路时可以规划路线，泡咖啡时可以继续交谈，有时还没来得及说清发生了什么，动作就已经作出了调整。不同的控制机制共同参与其中：有意识的思考帮助我们选择方向，小脑参与动作的协调，神经反射则无需等待有意识的判断就能迅速响应。它们相互配合、同时发生，不必在每一步轮流等待。

经验也会改变我们行动的方式。起初需要全神贯注的任务，练习后可以成为熟悉的技能。我们从一次尝试中学到东西，把有用的调整带到下一次，在情况需要时重新思考。思考、行动、响应和学习，就这样贯穿在持续进行的活动中。

**我们希望未来的 agent 成为自主控制系统：** 能够自主把目标落实为行动，判断何时继续、何时重新考虑，并根据任务需要协调工具、策略与其他 agent。它们应当能察觉结果与目标之间的偏差，调整做法，把经验积累成可复用的技能，同时在整个过程中持续回应你的指示。

**The Harness 是我们朝这个方向迈出的一步。** 模型思考并编写程序，程序与学习型策略执行动作，反应规则响应变化。执行与下一次决策可以同时进行，经过验证的学习成果可以在同一次运行中派上用场，应用于你接入的不同环境和能力。

## 自动运行

**系统持续感知和行动而不必停下来等待每一次思考。** 在持续变化的环境里，模型思考时，周围的事情仍在发生。The Harness 保持控制过程运行：正在执行的程序继续工作，反应规则检查它们关注的变化，模型则在需要时考虑接下来该做什么。

不同的变化可以在不同的层次得到处理。程序可以根据结果继续已有的流程，已配置的反应规则可以及时响应熟悉的情况；超出这些机制处理范围的问题，再交给模型重新判断。这样，一次思考所花的时间不必成为整个系统响应环境的等待时间。

这种连续性也贯穿程序之间的间隙。在按真实时间变化的环境中，一段程序结束后，系统仍能维持观测与反应，直到下一段工作接上。该继续的动作继续，该等待的操作等待，出现需要停止的条件也能及时中断。自动运行让这些过程持续衔接，同时保留随时重新判断和回应你指示的能力。

## 一次调用，多个动作

一次模型调用，为一段工作生成一个程序。程序可以组合工具和 skill，检查结果，并在已写出的流程内决定接下来做什么。

程序也可以使用**学习型策略**。程序将一段动作交给策略，以有界执行的方式运行，再检查结果、继续工作。环境适配器负责转换观测和动作；完成与中断沿用其他 skill 的执行生命周期。

模型在**决策点**回来：任务开始、程序结束、你发来消息，或出现需要重新判断的事件。它读取程序报告的结果和未解决的事件，再决定如何继续。只要运行中的代码还能处理当前情况，已有决策就能继续发挥作用；需要时，也能重新考虑。

## 边想边做

执行一个决定和准备下一个决定，可以同时发生。长程序运行期间，模型可以提前准备一次后续决策，并说明适用条件。程序结束时，只有结果符合条件、相关输入仍然有效，这个答复才会生效。实际结果与预期不同时，就需要根据实际情况重新考虑。

独立的程序和反应规则可以在模型调用期间继续运行。guard 可以响应已知条件，无需等待模型回复；未解决的事件或你的消息可以触发新的决策。时间线展示思考与执行如何重叠。[观看与回放](/docs/zh-cn/use/replay/)

## 边做边学

开启学习后，agent 可以把经验变成能再次使用的东西：供查阅的笔记和记忆、可运行的 skill，以及响应熟悉情况的反应规则。这些内容保存在显式绑定的 **library** 中，模型权重保持不变。

可执行的新条目经过测试和准入后才会激活。通过准入的版本可以在同一次运行的程序间隙生效，让已检查的做法用于任务剩下的部分。记录一个观测、验证一个 skill，以及证明它改善了任务结果，是不同的步骤；library 保留各自的证据。

agent 可以先探索环境再执行任务，也可以在工作中提出新条目。冻结 library 后，后续运行可以使用同一份经验，而不再改变它。[学习环境](/docs/zh-cn/learn/learn-an-environment/) · [边做边学](/docs/zh-cn/learn/while-working/)

## 四层结构

The Harness 按四种职责组织控制。各层有自己的节奏，模型的思考不必决定每个动作和响应的速度。

<HarnessFigure label="The Harness 的四层结构：语言模型、程序与学习型策略、反应层、安全层。" />

| 层 | 运行时机 | 做什么 |
|---|---|---|
| 语言模型 | 决策点 | 理解观测和结果，规划，编写程序，回应你的消息 |
| 程序与学习型策略 | 程序运行期间 | 组合 skill 和工具，或调用学习型策略；每次 skill 调用作为有界执行运行，以完成或中断结束 |
| 反应层 | tick 的每个周期 | 执行 guard、反射和事件 handler，无需调用模型即可行动、停止执行或上报事件 |
| 安全层 | 命令执行前 | 在 worker 边界检查来自程序、策略和反应规则的命令；学到的规则不能改写这些约束 |

**tick 协调四层，不是第五层。** 它独立于模型调用推进执行、检查反应规则并处理中断。

在按真实时间推进的环境中，tick 在程序之间也维持控制周期。按步推进的环境随执行前进，事件型环境则在截止时间内等待操作结果。持续控制遵循环境自身的时钟，不意味着反复调用模型，也不意味着没有工作时仍不断发出动作。

worker 负责环境运行，并在执行边界落实安全检查。

这里描述的是职责，不是四个进程或四个依次经过的阶段。事件可以把问题交给能够处理它的那一层：guard 结束一次执行，由程序处理事件；未解决的事件再到决策点交给模型。

## 接上你已经在用的工具

The Harness 可以双向连接：其他工具可以调用它，它的程序也可以使用其他工具。你可以选择不同组合，而不必把控制结构绑定到某一个模型、应用或环境。

| 连接 | 如何协作 |
|---|---|
| 应用 | OpenCode、Cursor、Codex 等 MCP 客户端可以把任务交给 The Harness 并跟进会话；ACP 编辑器可以从 agent 面板使用它。 |
| 环境 | 包提供桌面、浏览器、项目工作区、游戏或机器人所需的观测、命令、worker、skill 和 prompt。 |
| 模型 | 配置的托管 provider 或你自行运行的模型服务负责模型决策。 |
| MCP 服务器 | 程序在明确授权下使用已连接服务器的工具，例如 agent-desktop 或你自己的服务。 |
| Agent | 其他 agent 可以通过 MCP 驱动 The Harness，也可以通过支持的终端或 ACP 适配器在托管会话中运行。 |
| 学习型策略 | 程序通过适配器，将有界执行交给策略，并检查结果。 |

外部 agent 保留自己的决策过程，托管它不会把它的内部实现变成 The Harness 的四层结构。会话提供查看工作和传达指示的地方。Agent Skills 则提供模型按需查阅的说明。

默认情况下，你选择的任务或能力需要哪些包，就按需安装哪些包。安装 core 不会替你选择无关的外部 app 或 agent。[接入其他工具](/docs/zh-cn/extend/integrations/)

## 你始终在回路里

任务运行时，你仍然可以引导它。补充背景或改变一个要求，模型会考虑哪些工作继续、哪些完成、哪些停下。你可以跟进时间线、在执行前审阅程序，也可以在支持的电脑工作区暂停并接手操作。可用的审批和接管行为取决于工作区及其设置。[中途插话和接手](/docs/zh-cn/use/interrupt/)

core 执行有界任务，每个任务拥有自己的上下文、预算和执行记录。程序结束提供了需要检查的证据，本身并不等于目标已经达成。可选的 agent package 加入跨任务的身份、多轮对话和个人记忆；core 可以独立运行和学习。你可以把对话留在自己想用的地方，让 The Harness 接手其中的工作。

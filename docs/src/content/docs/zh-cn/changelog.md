title: 变更记录
---

首个公开快照正在准备中。公开版本的变更将在这里记录。

## 0.82.0

- ACP agent（Claude Code、Codex 以及 ACP Registry 里的其他 agent）可以当作 Harness agent 的模型：`models.json` 里 provider 为 `acp:ID` 的条目现在让 Harness agent 用它做决策，程序、工作区、学习和 library 都可用；以前选这个条目会启动 agent 自己的会话。要启动 agent 自己在目录里的会话，用 `--agent acp:ID`；`--agent` 加 `--library` 现在会报错，不再被悄悄忽略。`harness agents update` 不再返回 HTTP 403。
- 把 ACP agent 当作模型时，一次运行内会持续使用同一个会话：只是去掉了旧图片、丢弃了未采用的回复、或系统提示局部变化的调用，不再重发整个对话。对话结束或更换模型时，agent 的进程随之结束。agent 无法设置的模型或推理档位现在会报错，不再被忽略；填 `"default"` 表示使用 agent 自己的选择。
- 终端聊天会按原样显示 agent 回答里像 HTML 的文字，不再把它丢掉：`Vec<String>` 不会再只剩 `Vec`，以 `<div>` 等标签开头的一行也不会再连同后面几行一起消失。`<br>` 显示为换行，`<kbd>` 保留按键样式。
- 在终端对话里输入 `/approve ` 会提示 app、session 和 always，不再弹出错误页面。
- 给模型的内容处处有上限，有省略的地方会明说。 - 对话改为压缩而不是截断：一次调用读到的上下文达到 `runtime.compact_at_tokens`（默认 150000）时，模型写一份摘要，替换掉最近消息（最后 1 万到 4 万 token，至少五条）之前的对话。模型超过 `runtime.clear_results_after_minutes`（默认 60）没有回复、服务商缓存已冷时，除最近五个以外的程序结果被清掉。发给 OpenRouter 上 Anthropic 和 Qwen 模型的请求会给系统提示词和最后一条消息打上缓存标记。`runtime.max_history_turns` 已移除（仍设置它的配置会被拒绝），改用 `compact_at_tokens`。trace 记录 `compaction`，不再有 `context_shortened`。 - 单元打印或返回的内容在 30,000 字符以内完整告知（原来截到 8,000 和 2,000）；超过时存成程序可读的文件，模型看到文件位置和开头 2,000 字符。`output_of` 最多读 30,000 字符。 - 每一轮只告诉模型反射树里有多少个会行动的节点、上次告知以来哪些有变化（最多 10 个），不再发整棵树。`reflexes()` 给出顶层节点，`reflexes("name")` 给出某节点下面的节点，一次最多 50 个；节点的 `under` 现在是它下面节点的名字。 - 系统提示词在各次调用之间保持不变：主动学习的运行学到了什么，随程序结果告知，有变化时才完整给出。库里的技能列表不超过 8,000 字符（超出部分只列名字），笔记不超过 200 行或 25,000 字符。
- 能在自己那边运行代码的环境提供感知量：`sense(name, code)` 让环境每次报告状态时用它自己的语言算出一个值，规则和树的条件用 `view["sensed"][name]` 读它，程序用 `get_state()["sensed"][name]` 读它。条件原先在状态里看不到的东西只需定义一次，反应层和程序共用。worker 在 profile 里声明 `"senses": True` 并提供 `sense`、`senses`、`drop_sense` 即可。
- 环境可以把自己发生的事情作为一条消息告诉模型。运行为此保留了一个入口 `TaskRun.tell(content)`：`content` 是一个字符串，或者像对话内容那样由文字和图片组成的列表，它会立刻到达模型（等待结束，在途的调用重新询问），模型读到的是"Message from the environment"。profile 里写着 `"tells": True` 的 worker 会被告知往哪里说（`tell_to`），它的 `tell(content)` 把消息投递过去并立刻返回；`BenchWorker` 两者都有。不为此按时间读取任何东西，没有声明 `tells` 的 worker 行为与之前相同。监听只在运行所在的这台电脑上。
- 反射的条件偶尔慢一下，不再让树失去节点。某个周期里因为前面的节点把预算用完而没轮到判断的节点，改为下一个周期再判断，不再被移除；条件超过预算要连续三次才算故障。此前，一个条件超出预算 0.6 毫秒就移除了整棵树的全部节点。 模型是某个 agent 的会话时（`acp` 后端），压缩后的对话现在会开一个新会话，只带摘要和最近的消息。此前它会在旧会话里继续，而旧会话仍保留着全部内容：上下文没有变小，于是每次调用前都再压缩一次。
- 环境可以说明它交给 agent 使用的东西放在哪些目录（worker 的 profile：`"references": [path, ...]`）：程序所调用的库的文档和源码。程序可以读这些目录，模型在第一条消息里得知它们的位置。核心提示词说明：交给 agent 使用的东西也是“现有的东西”的一部分；在依赖一个不是自己做的东西之前，要从它本身弄清它做什么、默认假设什么、哪些留给 agent 决定，而不是凭对它的印象。
- session host 停掉后，终端对话会在大约 15 秒内说明情况，不再一直显示 working；agent 工作时连按两次 Ctrl+C 也能退出。
- 用 `harness install` 或 `harness remove` 安装、删除或更新的包，下一个对话就能用上：session host 会在没有打开的会话时自动重启，不再需要手动 `/host stop`。
- 核心提示词里的原则整体重写成一套，取代原来分开的三段。世界自己在走；替模型行动的有三样，快慢不同（模型带着判断、程序一步步、反射立刻），工作就是把每一种可能出现的情况交给合适的那一样。由此推出：从现有的出发，把任务需要的东西说成一组必须成立的事，而不是一串步骤；说清会出现什么（危险、反复出现的需要、恰好够得着的所需之物、失败的动作），不能等的在它出现之前交给反射；把反射树作为整体来设计，做到完备（每种情况都有节点）和自洽（节点的先后由此刻不出手的代价决定，条件是模型的完整判断）；造和测的力度与失败代价相称，出了问题修它所属的那一类。 学习运行的指令说明练习时间用来做什么：还做不成的事，自下而上，每一部分做到可靠再去学依赖它的；一个部分花多少时间与它失败的可能和代价成比例；环境允许时直接布置出要练的情境。 每个单元结束时都给出同一份报告，不论是谁启动的：怎么结束的（`ended`：自己跑完、出错、某个事件、被取消、到了时限）和它要办的事办成了没有（`done`），这是两回事。单元要办的事是它的完成条件：程序里的 `until(condition)`、`spawn(fn, until=condition)`；反射的程序则是"反射的条件不再成立"。反射的程序结束时情况还没过去，就算没办成：同一处后面的节点得到环境，或者把程序的报告告诉模型（以前只有抛出异常的程序才算失败，反射可以长时间无效地行动而模型不知情）。模型看到的程序结果开头从 `Program N status: ok` 变为 `Program N ended: by itself; done: no` 这样的形式。反射的优先级为 0 或更大，每个反射都从模型的程序手里接管环境：模型主动要做的事是它自己的程序，不是反射。 学习运行的指令是三小段：这是练习、有多少实时时间及其留下什么、什么算学会：一件事不靠帮助办成了不止一次，而且起点是它前面那些部分真正留下的状态。它不再规定按什么顺序练习，也不再说明代码如何被采纳和 situations 条目。 能暂停的环境会被告知是谁接管的（`pause(episode_id, by)`），被保持的一方恢复时可以知道自己被打断过、被谁打断。 核心提示词说明了反应层是做什么的。Agent 做两种事：应对发生在它身上和身边的事、应对完还在原处（它的反射树，自己运行，不经过模型）；以及主动去让一件原本不成立的事成立（模型的事，由它的程序去做）。树要整体设计，不是出了什么事就长一块：会发生在 agent 身上的每一类事都有节点，模型还不会应对的那一类有一个告诉它的节点；学会的做事方法是技能，不是节点。每一轮都会告诉模型树的近况：有哪些节点，每个节点的程序启动、办成、没办成各几次；树是空的也会明说。
- 学习运行现在可以留下 agent 自己写的 skill 和反应规则。新设置 `learning.admission`（`HARNESS_LEARNING_ADMISSION` 优先于它）决定这类代码如何被接纳：`fixture`（默认，与之前相同：只靠这台电脑为该条目提供的 fixture）、`own_test`（环境报告 `physical: false` 时，宿主还会在两个程序之间运行条目自带的测试；通过则以 provisional 接纳，显示为 `provisional (own test)`，该 library 之后的运行会加载它）或 `off`（不接纳也不加载任何学到的代码）。靠自带测试接纳的条目，记录满 3 次使用且成功不足四分之一时退回待验证。`harness library show` 会为每个代码条目标明它是由 fixture 还是自带测试接纳的。
- 反应层是一棵树，只有一个调用往树上放节点：`set_reflex(name, when, do=None, under=None, priority=0, every=None, again_seconds=0)`。`when` 是看视图的条件或事件名；`do` 是程序、要发出的事件名、结束执行的动作（`"stop"`），或不写：此时节点是一个组，供挂在它下面的节点使用。挂在另一个节点下面的节点，只有在上面那个节点的条件成立时才轮到；同一处的节点里靠前的从靠后的手里接管环境，做完还回去；节点的程序失败且同一处后面没有节点接手时，告诉模型（`REFLEX_FAILED`）。树顶优先级低于 0 的节点只在模型没有程序运行时才轮到。 以下已删除，不保留兼容：`tree`、`subtree`、`select`、`sequence`、`branch`、`do`、`check`、`raise_event`、`ref`、`when`、`watch`（守卫）、`on`、事件 `BRANCH_FAILED`，以及 `set_reflex` 的参数 `ends`、`min_seconds`、`while_holds`、`reads`、`raises`。守卫写作 `set_reflex(name, condition, "stop")`，给模型的事件写作 `set_reflex(name, condition, "NAME")`，事件的处理写作 `set_reflex(name, "EVENT", program)`。学到的 reactive 条目就是设置其节点的 `set_reflex` 那几行。
- 你发起的对话不再隔离：agent 的程序以你的身份在你的电脑上运行。它们能读你的文件，超出自己文件夹的事按你的审批处理：`approvals.programs`（`never`、`ask_each`、默认 `ask_once_session`、`allow`）和 `approvals.rules`（针对 `command`、`network`、`write` 的 `{level, action, match}`）决定程序能否运行命令、访问网络、在别处写文件；打开凭据文件和在别处删除永远等你点头。没有人可问时，需要询问的级别会拒绝，并告诉程序原因。隔离保持原样，作为评测的设置：实验仍是 `runtime.isolation = "auto"`。 程序可以用 `fetch(url)` 读网页、用 `search(query)` 搜索（`web` skill，app 的对话默认启用；搜索需要 `runtime.search`，即 OpenRouter 上一个带联网搜索插件的模型）。
- 程序用 `at_priority(n)` 在反射中间取得自己的位置：从这个调用到程序结束，它以优先级 n 持有环境。优先级为 n 或更高的反射仍然能从它手里接管环境；低于它的等待，程序结束后重新判断，每个被挡住的反射会告知模型一次。`uninterruptible()` 已移除：它把所有反射都挡在外面，包括那些应对与程序无关的危险的反射。确实不能被任何东西打断的程序，用一个高于最高反射的数调用 `at_priority`。
- 反应在开始时就告诉模型。规则的程序（优先级更高的单元）从一次正在进行的调用手里接管环境时，模型会立即得知，和每个到达它的事件一样：哪条规则接管了环境、从哪个程序手里、以及当时的状态；等待结束，正在进行的模型调用被重新发起。被打断的调用在当前位置以事件 `PREEMPTED` 结束，并带着它已经做了的事，接下来做什么由模型决定。接管环境的单元持有环境直到自己结束：模型在此期间启动的东西排在它之后，等它结束再继续。 不再兼容的部分：被打断的调用不再自动重新启动。需要时用 `spawn(fn, restart=True)` 要求（默认值原来是 `restart=True`，现在是 `restart=False`）；调用被打断的程序会以 `PREEMPTED` 结束，除非有 handler 处理它（`on("PREEMPTED", ...)`）。`preempted` 记录还会写出规则、单元和执行的名字。
- 规则可以组织成一棵树，和游戏角色的行为树一样：`tree(root)`，节点有 `select`、`sequence`、`branch`、`do`、`check`、`raise_event` 以及 `ref`/`subtree`。节点的位置就是它的优先级；放在树的某一部分之上的条件对它下面的一切都成立；用 `subtree` 命名的部分可以在任意多处使用，只需在一处修改。树自己运行：被接管的部分会被结束，树再次被判断时回到它；树自己的程序结束时只做记录，不引起对模型的调用；当某个叶子的程序失败而树里没有别的部分接手时，模型会被告知（事件 `BRANCH_FAILED`）。`rules_set()` 显示各棵树和正在运行的分支，`clear_rules(name)` 移除一棵树。用 `rule`、`when`、`watch` 设置的规则和以前一样，与树并存。
- 反射的条件偶尔一次被强制中止（超过预算的四倍），不再让树失去这个节点：节点保持原来的结果，下一个周期再判断，连续三次才算故障。此前机器卡顿 20 毫秒就会立刻移除节点。
- 学习相关的提示词与调用用词一致：学习目标、库的说明和反思提示词原先把同一个东西叫作 reactive rule，现在统一称 reflex。
- 设置自己行动的规则的调用改为 `set_reflex(name, when, do=None, ...)`；`reflexes()` 列出它们，`drop_reflex(names=None)` 移除它们。它们取代 `rule`、`rules_set` 和 `clear_rules`：调用旧名字的程序和库条目需要改名（名字在最前，条件是 `when`，程序是 `do`）。 环境如果能把一个调用正在做的事保持住、之后让它继续，就在 worker 的 profile 里声明 `"pauses": True` 并提供 `pause` 和 `resume`。在这样的环境里，优先级高的单元不再结束它所接管的调用：该调用被暂停，高优先级单元行动，等它结束后调用接着进行，仍在同一个程序里，也不询问模型。trace 记录 `call_paused` 和 `call_resumed`。不能暂停的环境行为不变（调用以 PREEMPTED 结束）。 反射的程序正常结束时只记录、不再唤醒模型；失败时仍会告知。学到的 reactive 条目在加载时除了反射也可以设置树；条目里 lambda 的函数体和函数一样算作之后才运行的代码：像 `set_reflex("low", lambda view: view["facts"].get("low"), refill)` 这样的条目现在可以加载，以前会被拒绝。
- `answer=$(harness run "task" -p)` 会在终端里询问在哪里工作，不再报错：回答进管道，问题走 stderr； 没有终端时，给人看的错误只有一行，只有程序读取时才输出 JSON。
- 为其他 Harness 版本制作的包不再让所有对话失败：session host 会跳过它，`harness doctor` 和需要它的任务会写明是哪个包，并提示运行 `harness install --update`。
- 模型可以读取正在运行的单元到目前为止打印的内容：用单元的名字调用 `output_of(unit)`（或对 `entries()` 给出的句柄调用 `.output()`），得到最后的若干字符（默认 2000，最多 4000），并且不会从单元的结果里取走它们。一次等待结束时，每个正在运行的程序都会列出它上一次打印是多久以前；核心提示词现在说明，留下仍在运行的工作由模型自己看管：继续等待之前先检查，没有按预期进行时就取消。隔离工作区里的程序仍然只在结束时给出它的输出。
- 核心提示词在"怎么造、怎么测"的原则旁边加了一条关于时间的原则：你的回复要几秒，程序在下一步才响应，反射立刻响应；开始一件事之前，先说清可能发生哪些需要更快响应的事，并在去到它可能发生的地方之前把反射设好。 学习环境的运行，其指令不再规定怎么学。它只说明：这是练习、有多少实时时间、库和环境保留的东西就是任务运行开局拥有的全部、什么算学会、提交的代码如何被采纳。原来的六个步骤删除；每个程序之后的"Next: ……"提示和库清单里的"先用这些"也删除，那里只告诉模型库里有什么、什么还在等待。
- 终端聊天里，带默认值的输入框（设置项、项目文件夹）和取消启动后保留在输入框里的消息，都从末尾接着输入；新对话在选择环境时取消或启动失败后， 后续消息不再发给已结束的对话。拒绝理由留空按 Enter 会直接拒绝，Ctrl+O 详情里的程序输出保持分行， models.json 存坏后 `/models` 仍能打开它进行修改。
- 对话会一直继续，直到你结束它。agent 的回答（一条纯文本回复）结束的是它的这一轮，不是对话：下一条消息发给同一个对话，它保留自己的消息、程序的变量、规则、facts 和环境。agent 留下仍在运行的东西在回答之后继续运行，某个单元结束或有事件到达时，不需要消息就开始它的下一轮。模型调用次数和时间是一轮的上限，随下一轮重新开始；达到上限、出错或被取消（`/cancel`）的一轮带着这个原因结束，对话继续等待；费用按整个对话统计。每一轮以一条 `turn_result` 记录结束。`/clear` 是 `/new` 的另一个名字。session 随进行随时写到磁盘上（trace 旁边的 `conversation.json`），已经结束的 session 用一个新的 kernel 在它自己的 session id 里继续：`harness --continue`、`harness --resume ID`、`harness run --continue | --session ID "task"`、`harness sessions resume ID`、`/resume`、`Host.resume_session()`；旧进程里的东西（变量、规则、正在运行的程序）没有了，agent 会被告知。一轮结束的子 agent 可以再收到消息（`send_agent`），并带着它的历史继续。工作区被别的对话需要的对话会被暂存，它的下一条消息让它继续。没有用户的运行同样保留它的对话：`harness program CONFIG --continue EPISODE --message "..."` 让该目录里的 episode 在它自己的 session 里、对着正在运行的 worker 再走一轮。 不再兼容的部分：提示词不再教 `<finish>`；`<finish>` 和 `finish()` 仍被接受，含义与纯文本回答相同。在没有用户的运行（benchmark）里，纯文本回复现在作为回答结束这次运行，不再被当作格式错误退回。原来在回答之后等待 `FINISHED` 的前端，改为等待 `turn_result` 记录（之后的状态是 `IDLE`，它的 `reason` 说明这一轮怎样结束）；`harness run "task"` 和 MCP server 的 `run_task` 仍然在这一轮之后结束它们启动的 session。子 agent 的报告不再有 `question`，也没有 `asks` 状态：它问的问题就是它的回答。ACP 的 `session/cancel` 结束这一轮并保留对话。agent package（`harness agent`）交出的任务随它的这一轮结束，所以它提的问题会作为任务的回答返回。在 `summary.json` 里，在两轮之间被关闭的对话保留最后一轮的状态；`closed` 表示一轮被中途打断。评测结果仍在对话结束时读取，因为 worker 只评一次。kernel 死掉会结束对话；用 `--resume` 继续它。终端对话里的 Esc 仍然是暂停。
- 程序可以一直持有环境：调用 `uninterruptible()` 之后，直到它结束，不管优先级多少，任何规则的程序和其他单元都不会从它手里接管环境。期间条件成立的规则不会行动；程序结束后重新判断，条件仍然成立才行动，模型会被告知一次该规则被挡住（事件 `HELD_BACK`）。取消这个程序、它的调用到时限、结束执行的规则以及 episode 结束，仍然会结束它。`rules_set()` 按优先级从高到低列出现有的规则及其优先级。数字优先级不变。
- 一次运行现在由一个模型和它启动的单元组成。模型写的每个程序都作为一个单元与其他单元并排运行，各有自己的输出和结果：模型的这一轮立刻回来（程序在 `runtime.turn_grace_seconds`（默认 2 秒）内结束时带着结果，否则程序仍在运行），模型可以再启动一个程序、取消一个，或者回复 `<wait>`，直到某个单元结束、有消息或事件到达、或时间到（`runtime.longest_wait_seconds`）。规则是一个条件、一个优先级和一个程序：`rule(begins, program, ends=..., priority=...)` 在条件变为成立时把程序作为单元启动；`facts` 是程序和规则条件共享的命名值存储。优先级高的单元从优先级低的单元手里接管环境，低优先级的那次调用之后被重新启动。子 agent 结束时会唤醒启动它的模型。 不再兼容的部分：程序运行期间的前瞻（`<assume>`）、`watch(every=秒数)`、反射规则（`reflex`、`remove_reflex`、命名优先级）和 `USER_MESSAGE` 事件已移除；`runtime.think_while_acting`、`model.think_while_acting` 和 `--think` 仍被接受，但不起作用。worker 的 profile 用 `max_hz` 和 `step_seconds` 说明它如何被驱动，不再用 `clock`（旧的 `clock` 仍可读取）；没有东西运行时每个周期也需要命令的环境，现在需要一条按时间判断的规则。暂停会停下每个单元，直到对话继续。trace 去掉了 `ahead`、`side_program`、`side_program_end` 和 `program_stopped`，新增 `unit_end`、`wait`、`wait_end`、`rule`、`fact` 和 `preempted`。
- worker 自己的方法可以有名为 `name` 的参数：直接调用它或通过挂载的环境调用它，不再报错 "got multiple values for argument 'name'"。
- 核心提示词说明了工作方式：为一个东西需要起作用的那些情况而做；在失败代价高的地方运行它之前，列出它的假设；对不确定又要紧的假设，用能证明它错的最小测试去验证；失败之后，修复对这一类情况负责的部分，并在别处寻找同样的缺陷。

The first public snapshot is being prepared. Changes to public releases will be recorded here.

## 0.83.0

- The approvals setting and the Permissions page say which environments recognize a sensitive step today; a project folder's commands and file writes are not checked yet, so they wait only with `approvals.ask = "programs"`.
- The model is no longer told with every call what the run has left (its model calls, its environment steps, its live time): the host keeps the limits and ends the turn at them. A run that needs the countdown, such as a benchmark whose episodes are a few dozen calls, sets `runtime.tell_budget = "always"` to get it as before. The reflection prompt no longer says anything that belongs to one game.
- `harness --help` and the package description call The Harness Automatic Control for intelligence in action.
- What reaches the model by itself goes through one queue with three priorities. An event, what the environment tells and a unit that ended with an error set the call in flight aside (`now`); the end of a unit and a message of the user are told with the next call (`next`); a reflex held back by a program's priority is told after the model's next wait (`later`). With every call the model is told, in the same order, what its last reply came to, what reached it, and how things stand now: the state, the units that run, what changed in the tree of reflexes and the calls left, also when a wait only ran out. What changes for you: a message sent while the model writes a reply no longer sets that reply aside, the reply is done first; pause (Esc or Stop) to stop it where it is. An event reads `Event KIND from SOURCE: ...` in place of `Unresolved event: {...}`.
- The core prompt says how the tree of reflexes is organised: a node is a situation, the nodes under it divide it further, and the last of them answers what none of the others does, at every depth. What happens to the agent whatever it is doing belongs in the tree, not in the program that was running when it happened.

## 0.82.0

- An ACP agent (Claude Code, Codex and the others of the ACP Registry) can be the model of the Harness agent: a `models.json` entry with the provider `acp:ID` now gives the Harness agent that model, with programs, workspaces, learning and libraries, where it used to start the agent's own session. For the agent's own session in a folder, name it with `--agent acp:ID`; `--library` with `--agent` is now an error instead of being ignored. `harness agents update` no longer fails with HTTP 403.
- An ACP agent used as the model keeps its session across a run: a call that only drops an old picture, leaves out a reply that was not kept, or changes part of the system prompt goes on in the same session instead of sending the whole conversation again. The agent's process ends when the conversation ends or the model is changed. A model or reasoning effort the agent cannot set is now an error instead of being ignored: write `"default"` to take the agent's own.
- The terminal chat shows the agent's text that looks like HTML as it was written instead of leaving it out: `Vec<String>` no longer reads `Vec`, and a line that starts with a tag such as `<div>` no longer hides itself and the lines after it. `<br>` breaks the line and `<kbd>` keeps its style.
- Typing `/approve ` in the terminal chat offers app, session and always instead of stopping the chat with an error screen.
- What the model is given has a limit everywhere, and says so where it leaves something out. - A conversation is compacted instead of cut: when the context a call read reaches `runtime.compact_at_tokens` (default 150000), the model writes a summary, which replaces the conversation before its recent messages (the last 10,000 to 40,000 tokens, at least five messages). After `runtime.clear_results_after_minutes` (default 60) without a reply, when the provider's cache is cold, the results of all programs but the last five are cleared. Requests to Anthropic's and Qwen's models on OpenRouter mark the system prompt and the last message for the provider's cache. `runtime.max_history_turns` is gone (a configuration that sets it is refused): set `compact_at_tokens` instead. The trace records `compaction`; `context_shortened` is gone. - What a unit printed or returned is told whole up to 30,000 characters (it was cut to 8,000 and 2,000); more is saved to a file a program can read, and the model is told the file and the first 2,000 characters. `output_of` reads up to 30,000 characters. - Every turn tells how many nodes act in the tree of reflexes and which changed since the model was last told (at most 10), not the whole tree. `reflexes()` gives the nodes at the top and `reflexes("name")` those under a node, at most 50 at a time; a node's `under` is now the names of the nodes under it. - The system prompt stays the same from call to call: what an active run has learned is told with a program's result, whole when it changed. The library's skills are listed within 8,000 characters (past that by name only) and its notes within 200 lines or 25,000 characters.
- An environment that can run code where it is offers senses: `sense(name, code)` has it compute a value in its own language each time it reports its state, and conditions of rules and trees read it as `view["sensed"][name]`, programs as `get_state()["sensed"][name]`. What a condition could not see in the reported state is defined once and serves the reactive layer and programs alike. A worker offers it with `"senses": True` in its profile and the methods `sense`, `senses` and `drop_sense`.
- An environment can tell the model what happens in it by itself, as a message. A run has an entry for it, `TaskRun.tell(content)`: `content` is a string or a list of text and image parts, as conversations give content, and it reaches the model at once (a wait ends, a call in flight is asked again), read as "Message from the environment". A worker whose profile says `"tells": True` is given where to tell (`tell_to`), and its `tell(content)` posts there and returns at once; `BenchWorker` has both. Nothing is read on time for it, and workers that do not say `tells` behave as before. The listener is on the run's own computer.
- A reflex whose condition is slow for a moment no longer costs the tree its nodes. The nodes a period had no time for, because one before them used its budget up, are judged in the next period instead of being removed, and a condition that takes longer than the budget counts as a fault only when it does so three times in a row. Before, one condition 0.6 ms over its budget removed every node of a tree. With a model that is a session of an agent (the `acp` backend), a compacted conversation now starts a new session that holds the summary and the recent messages. It used to go on in the old session, which still held everything: the context did not shrink and the conversation was compacted again before every call.
- An environment can name the folders that hold what it gives the agent to act with (a worker's profile: `"references": [path, ...]`): the documentation and source of the libraries its programs call. Programs may read them, and the model is told where they are with its first message. The core prompt says that what the agent is given to act with is part of what is there: before relying on something it did not make, it finds out from the thing itself what it does, what it assumes and what it leaves to the agent, not from what it remembers of it.
- When the session host stops, the terminal chat says so within about 15 seconds and stops showing the conversation as working, instead of spinning forever; Ctrl+C twice leaves the chat also while the agent works.
- Packages installed, removed or updated with `harness install` or `harness remove` reach the next conversation: the session host restarts by itself once no session is open, instead of waiting for `/host stop`.
- The principles of the core prompt are written anew as one whole, in place of three separate paragraphs. The world goes on by itself; three things act for the model at three speeds (the model with judgement, a program step by step, a reflex at once), and the work is to give every situation that can arise to the one that fits it. From that: start from what is there and say what the task needs as things that must be true, not as a sequence; say what can arise (a danger, a need that returns, something needed that comes within reach, an action that fails) and give what cannot wait to a reflex before it can arise; design the tree of reflexes as a whole, complete (every situation has a node) and consistent (a node's place is what it costs when it does not act now, and its condition is the model's whole judgement); build and test in proportion to what a failure costs, and repair the kind a failure belongs to. The instruction of a learning run says what practice time is for: what does not work yet, from the ground up, each part made reliable before what depends on it, with time in proportion to how likely a part is to fail and what its failure costs, in a situation set up directly where the environment allows it. Every unit ends with the same report, whoever started it: how it ended (`ended`: by itself, an error, an event, cancelled, its time limit) and whether what it was for is the case (`done`), which are two things. What a unit is for is its completion condition: `until(condition)` in a program, `spawn(fn, until=condition)`, and for a reflex's program that the reflex's condition no longer holds. A reflex whose program ended with its situation not over has not done its work: a later node at its place has the environment, or the model is told with the program's report (before, only a program that raised counted as failed, and a reflex could act for a long time without effect and without the model knowing). What the model is told of a program begins `Program N ended: by itself; done: no` instead of `Program N status: ok`. A reflex's priority is 0 or more, and every reflex takes the environment from the model's programs: what the model pursues is its own program, not a reflex. The instruction of a learning run is three short paragraphs: that it is practice, its live time and what remains of it, and what counts as learned: something has done its work without help, more than once, starting from what the parts before it really leave. It no longer says in which order to practise, how code is admitted, or anything of the situations entry. An environment that pauses is told who takes it (`pause(episode_id, by)`), so that what it holds can know, when it goes on, that it was interrupted and by what. The core prompt says what the reactive layer is for. An agent does two kinds of things: it answers what happens to it and around it and is then where it was (its tree of reflexes, acting by itself, without the model), and it sets out to make something the case that is not (the model's, done by its programs). The tree is designed as a whole, not grown from what went wrong last: every kind of thing that can happen to the agent gets a node, and a kind the model cannot answer yet gets one that tells it; a way of doing something that was learned is a skill, not a node. Every turn the model is told how the tree stands: its nodes and how often each one's program began, did its work and did not, and that it is empty when it is.
- A learning run can keep the skills and reactive rules the agent writes itself. The new setting `learning.admission` (`HARNESS_LEARNING_ADMISSION` wins over it) says how such code is admitted: `fixture` (the default, as before: only a fixture this computer provides for the entry), `own_test` (where the environment reports `physical: false`, the host also runs the entry's own test between programs; a pass admits it as provisional, shown as `provisional (own test)`, and later runs of the library load it), or `off` (no learned code is admitted or loaded). An entry admitted by its own test goes back to pending once 3 uses of it are recorded and fewer than a quarter succeeded. `harness library show` says for each code entry whether a fixture or its own test admitted it.
- The reactive layer is one tree, and one call puts a node into it: `set_reflex(name, when, do=None, under=None, priority=0, every=None, again_seconds=0)`. `when` is a condition of the view or the name of an event; `do` is a program, the name of an event to raise, an action that ends what runs (`"stop"`), or nothing: then the node is a group for the nodes set under it. A node under another has its turn only while that one's condition holds; among the nodes at one place the earlier takes the environment from the later and gives it back; when a node's program fails and no later node at its place takes the environment, the model is told (`REFLEX_FAILED`). A node at the top with a priority below 0 has its turn only while no program of the model runs. Removed, with nothing kept for compatibility: `tree`, `subtree`, `select`, `sequence`, `branch`, `do`, `check`, `raise_event`, `ref`, `when`, `watch` (the guard), `on`, the event `BRANCH_FAILED`, and of `set_reflex` the parameters `ends`, `min_seconds`, `while_holds`, `reads` and `raises`. A guard is `set_reflex(name, condition, "stop")`, an event to the model `set_reflex(name, condition, "NAME")`, a handler `set_reflex(name, "EVENT", program)`. A learned reactive entry is the `set_reflex` lines that set its nodes.
- A conversation you start is no longer isolated: the agent's programs run on your computer as you. They read your files, and what they do beyond their own folder goes by your approvals: `approvals.programs` (`never`, `ask_each`, `ask_once_session` by default, `allow`) and `approvals.rules` (`{level, action, match}` for `command`, `network` or `write`) decide whether a program may run a command, reach the network or write a file elsewhere; opening a file of credentials and deleting elsewhere always wait for you. Where nobody can be asked, a level that asks refuses and tells the program why. Isolation stays what it was, as the setting of evaluations: experiments keep `runtime.isolation = "auto"`. Programs can read a page with `fetch(url)` and search with `search(query)` (the `web` skill, on in the app's conversations; a search needs `runtime.search`, a model on OpenRouter whose web plugin searches).
- A program takes its place among the reflexes with `at_priority(n)`: from that call to its end it holds the environment with priority n. Reflexes of priority n or more still take the environment from it; those below wait and are judged again when it has ended, and the model is told once of each that was held back. `uninterruptible()` is gone: it shut every reflex out, the ones that answer a danger the program has nothing to do with as well. A program that must not be cut short by anything calls `at_priority` with a number above its highest reflex.
- A reaction tells the model when it begins. When a rule's program (a unit of higher priority) takes the environment from a call that runs, the model is told at once, as with every event that reaches it: which rule took the environment, from which program, and the state; a wait ends and a call that is out is asked again. The interrupted call ends there with the event `PREEMPTED` and what it had done, and the model decides what goes on. The unit that took the environment holds it until it ends: what the model starts meanwhile waits behind it and goes on then. What breaks: an interrupted call is no longer started again by itself. `spawn(fn, restart=True)` asks for that (the default was `restart=True`, it is `restart=False` now); a program whose call is interrupted ends with `PREEMPTED` unless a handler answers it (`on("PREEMPTED", ...)`). The `preempted` record also names the rule, the units and the execution.
- Rules can be organised in a tree, as the behavior trees of game characters are: `tree(root)` with `select`, `sequence`, `branch`, `do`, `check`, `raise_event` and `ref`/`subtree`. A node's place is its priority; a condition placed above a part of the tree holds for everything below it; a part named with `subtree` is used in any number of places and repaired in one. A tree runs by itself: what a node takes over from is ended and the tree returns to it when it is judged again, and the ends of the tree's own programs are recorded without starting a call of the model, which is told when a leaf's program fails and nothing else in the tree takes it (the event `BRANCH_FAILED`). `rules_set()` shows the trees with the branch that runs, and `clear_rules(name)` removes one. Rules set with `rule`, `when` and `watch` work as before, beside the trees.
- A reflex condition that had to be ended at the hard time limit (four times its budget) once no longer costs the tree its node: the node keeps what it was and is judged in the next period, and only three such periods in a row are a fault. Before, a stall of the machine of 20 ms removed the node at once.
- The learning prompts say reflex where the calls do: the learning goal, the library's instructions and the reflection prompt named the same thing a reactive rule.
- The call that sets a rule that acts by itself is `set_reflex(name, when, do=None, ...)`; `reflexes()` lists them and `drop_reflex(names=None)` removes them. They replace `rule`, `rules_set` and `clear_rules`: programs and library entries that call those change the names (the name comes first, the condition is `when`, the program is `do`). An environment that can hold what a call is doing and let it go on later says `"pauses": True` in its worker's profile and serves `pause` and `resume`. There a unit of higher priority no longer ends the call it takes the environment from: the call is paused, the higher unit acts, and the call goes on when that unit has ended, in the same program and without a question to the model. The trace records `call_paused` and `call_resumed`. Environments that do not pause behave as before (the call ends with PREEMPTED). A reflex's program that ended well is recorded and no longer wakes the model; its failure does. A learned reactive entry may set trees as well as reflexes when it is loaded, and the body of a lambda in it counts as code that runs later, like a function's: an entry such as `set_reflex("low", lambda view: view["facts"].get("low"), refill)` loads, where it was refused before.
- `answer=$(harness run "task" -p)` asks where to work on the terminal instead of failing, as the answer goes to the pipe and the question to stderr; without a terminal the error is one line for a person and JSON only for a program.
- A package made for another version of The Harness no longer stops every conversation: the session host leaves it out, and `harness doctor` and a task that needs it name the package and say to run `harness install --update`.
- The model can read what a running unit has printed so far: `output_of(unit)` with the unit's name (or `.output()` on its handle from `entries()`) gives the last characters (2000 by default, at most 4000) without taking them from the unit's result. When a wait is over, each running program is listed with how long ago it last printed, and the core prompt now says that work left running is the model's to supervise: check it before waiting again, and cancel it when it is not doing what was expected. A program in an isolated workspace still gives its output only when it ends.
- The core prompt has a principle about time beside the ones about building and testing: your reply takes seconds, a program answers at its next step, a reflex at once; before starting something, say what can happen that needs an answer sooner, and have a reflex in place before going where it can happen. The instruction of a run that learns its environment no longer says how to learn. It says that the run is practice, how much live time there is, that what the library and the environment keep is all the task's runs start with, what counts as learned, and how proposed code is admitted. The six steps are gone, and so are the "Next: ..." lines after each program and "use these first" in the library's listing: what the model is told there is what the library holds and what is pending.
- In the terminal chat, typing in a prefilled field (a setting, a project folder) or in a message kept after a cancelled start goes on from its end, and cancelling the environment choice of a new conversation, or a start that fails, no longer sends the next messages to the conversation that ended. Enter on an empty reason refuses without one, Ctrl+O details keep program output on separate lines, and `/models` opens a model list saved with a mistake so it can be corrected.
- A conversation goes on until you end it. The agent's answer, a reply in plain text, ends its turn, not the conversation: the next message goes to the same conversation, which keeps its messages, the variables of its programs, its rules, its facts and the environment. What the agent left running goes on after the answer, and the end of a unit or an event starts its next turn without a message. Model calls and time are limits of a turn and begin anew with the next one; a turn that reaches one, fails or is cancelled (`/cancel`) ends with that reason and the conversation waits; cost is counted for the whole conversation. Every turn ends with a `turn_result` record. `/clear` is another name of `/new`. Sessions are kept on disk as they go (`conversation.json` beside the trace), and one that ended is continued in its own session id with a new kernel: `harness --continue`, `harness --resume ID`, `harness run --continue | --session ID "task"`, `harness sessions resume ID`, `/resume`, `Host.resume_session()`; what lived in the old process (variables, rules, running programs) is gone, and the agent is told so. A sub-agent whose turn ended can be sent another message (`send_agent`) and goes on with its history. A conversation whose workspace is needed by another is parked, and its next message continues it. A run nobody talks to keeps its conversation as well: `harness program CONFIG --continue EPISODE --message "..."` gives the episode in that directory one more turn, in its own session, against the worker that runs. What breaks: the prompt no longer teaches `<finish>`; `<finish>` and `finish()` are still accepted and mean the same as a text answer. In a run without a user (a benchmark), a reply in plain text now ends the run as its answer instead of being sent back as a format error. A frontend that waited for `FINISHED` after an answer waits for the `turn_result` record instead (the state after it is `IDLE`, whose `reason` is how the turn ended); `harness run "task"` and the MCP server's `run_task` still end the session they started after its turn. A sub-agent's report has no `question` and no `asks` status: what it asks is its answer. ACP `session/cancel` ends the turn and keeps the conversation. A task the agent package gives (`harness agent`) ends with its turn, so a question it asks comes back as the task's answer. In `summary.json`, a conversation closed between turns keeps the status of its last turn; `closed` is a turn that was cut short. The evaluator's outcome is read when the conversation ends, as before, since a worker evaluates once. A kernel that dies ends the conversation; it is continued with `--resume`. Esc in the terminal chat still pauses.
- A program can keep the environment: after `uninterruptible()` no rule's program and no other unit takes the environment from it until it ends, whatever their priority. A rule whose condition comes to hold meanwhile does not act; it is judged again when the program has ended and acts if its condition still holds, and the model is told once that it was held back (the event `HELD_BACK`). Cancelling the program, the time of its calls, a rule that ends executions and the end of the episode still end it. `rules_set()` lists the rules that exist with their priority, highest first. Numeric priorities are unchanged.
- A run is now one model and the units it starts. Every program the model writes runs as a unit beside the others, with its own output and result: the model's turn comes back at once (with the result when the program was over within `runtime.turn_grace_seconds`, 2 s by default, else while it still runs), and the model may start another program, cancel one, or reply `<wait>` until a unit ends, a message or an event reaches it, or its time is over (`runtime.longest_wait_seconds`). A rule is a condition, a priority and a program: `rule(begins, program, ends=..., priority=...)` starts the program as a unit when its condition comes to hold; `facts` is a store of named values that programs and rule conditions share. A unit of higher priority takes the environment from a lower one, whose call is started again afterwards. A sub-agent that ends wakes the model that started it. What breaks: the look-ahead during a program (`<assume>`), `watch(every=seconds)`, the reflex rule (`reflex`, `remove_reflex`, the named priorities) and the `USER_MESSAGE` event are gone; `runtime.think_while_acting`, `model.think_while_acting` and `--think` are still accepted and have no effect. A worker's profile says how it is driven with `max_hz` and `step_seconds` instead of `clock` (an old `clock` is still read); an environment that needs a command every period while nothing runs now needs a rule on time. A pause stops every unit and holds until the conversation is continued. The traces lose `ahead`, `side_program`, `side_program_end` and `program_stopped` and gain `unit_end`, `wait`, `wait_end`, `rule`, `fact` and `preempted`.
- A worker's own method may take an argument called `name`: calling it, directly or through an attached environment, no longer fails with "got multiple values for argument 'name'".
- The core prompt says how to work: build for the situations a thing has to work in, list what it assumes before running it where a failure is costly, test the uncertain assumptions that matter with the smallest test that could prove them wrong, and after a failure repair the part responsible for that kind of situation and look for the same flaw elsewhere.

## 0.80.0 (unreleased)

A conversation's environment is no longer fixed by one saved setting, and its observation is no longer a fixed bundle per environment.

- **Each conversation chooses where it works.** The choice lists what the installed packages provide: no environment (conversation only: no worker, no view), a project folder, a background browser, background applications, your desktop, a separate display. `session.environment` is `ask` (the default: every new conversation asks, the last choice highlighted), `last`, or one kind. `computer.mode` is now the computer kind highlighted first; saved values keep working. The terminal has an opening choice and `/environment`, the app's composer has the two new choices, the command line takes `--workspace none|project|...`, and Python takes `workspace="none"`. Where nobody can be asked and the setting is `ask`, the task does not start and the error names the option.
- **One agent takes another environment when a step needs it.** `use_environment(kind, why)` attaches it to the same conversation and `release_environment(kind)` gives it back; its calls are under its name (`desktop.click(...)`, `project.run_command(...)`, `browser.read_page()`). `environments.attach` grades the permission (`never`, `ask_each`, `ask_once_session`, `allow`; default `ask_once_session`), with rules per kind. The question shows the model's reason. With `physical.level = "allow"` it does not ask; `never` still refuses; where nobody can be asked and the level asks, it is refused with the reason. Every attachment and its reason is in the conversation, the timeline and the trace. Real mouse and keyboard stay under the physical-input policy.
- **Sub-agents are off by default.** `session.agents`, `--agents`, `/agents`, the app's switch or `runtime={"agents": True}` turn them on, or the agent asks with `request_agents(why)` and you agree.
- **The model looks when it needs to.** Every turn is text. `look()` puts a view in the next turn with that program's result, `watch()` brings the views with every program (or every few seconds) until `unwatch()`, and a view stays for one reply unless the model keeps or pins it. A configuration that declares `runtime.cameras` keeps its standing watch unchanged: the resolved evaluation agent is byte-identical to 0.79.2 for its robot, desktop and game tables, and the robot packages are untouched.
- **Models that read no images.** Model entries record it (from the provider's catalog where it says; editable). Such a model is sent no image; `model.vision` names a model that describes a view for it; the environment choice says so beside environments with a screen.
- **The verifier** gets the state, the elements or page text the environment reports, and the views.

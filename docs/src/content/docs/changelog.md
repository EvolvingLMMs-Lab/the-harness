Changes in each public release are recorded below.

## 0.87.0

- A library entry admitted by its own test now has its text in the library's file. Such an admission recorded the new revision in the index, which is what loads, but left the file with the old text and removed the waiting copy, so anyone reading the file (a person, or a tool that copies the library) saw an entry other than the one in use. In one run a reactive tree changed and admitted by its own test was in the index while the file still held the tree from before.
- `atomic(seconds=5)` wraps a step of a program that must not be interrupted: no node of the tree takes the environment during it, and past its seconds the nodes may again. The prompt says to wrap only that step, as small as it can be.
- The tree of reflexes is judged as a behaviour tree. A node is a sequence of its condition and its action: `when` only decides whether the action begins, and the action then runs until it has a result. `over=` says when the situation is past: the action is ended there, its work done, and one that returns before that has failed. A node with nodes under it is a selector: the nodes under it in order, then its own action; a node that failed is not tried again in that occurrence of its situation, and the next acts. Order is the order in the tree (`before=`). This breaks set_reflex: `priority`, `again_seconds` and `while_holds` are gone, as are the timed retries (0.2 s, 2 s); at_priority takes the name of a node (its place) or nothing (above every node). Nothing of the tree is judged while the agent cannot act (a session's can_act).
- Where the environment pauses and declares channels, units share it by channel: a unit takes only the channels it claims (a node says them with set_reflex claims=), pauses only the lower units that use one of them, and the others go on beside it. The environment is told which channels to pause and is given the commands of units that start together as one (session._combine).
- `runtime.compact_at_share`: where the model says how many tokens it can read at most (an ACP agent does, in its usage updates), the conversation is compacted at this share of them instead of at the fixed `compact_at_tokens`, as Claude Code compacts at about 83% of the window. The summary is still asked for ahead at 70% of that limit. A model that says nothing keeps `compact_at_tokens`.
- The summary that compacts a conversation is written ahead: once the context reaches runtime.compact_arm_tokens (default 70% of compact_at_tokens) it is asked for in the background, beside the model's own calls, and put in at the limit, keeping the messages that came after it was asked for. The conversation waits only for what a summary not yet back has left, and writes one at the limit only where none was asked for or it failed. A long run used to stop for 43 to 70 s at each of its compactions.
- After a compaction, the message the next call ends with tells how things stand as they are then: the state, the units that run and the tree are built again after the summary, in place of the ones told before it. A summary takes its time (80 s in one run), and the world goes on meanwhile; the model had been told the inventory and the running program of before the summary and waited on a program that had already been cancelled.
- A library function called while a reflex's condition is judged no longer writes a step record per call. Those records counted against the condition's time budget: a condition built from several helper functions went over its 5 ms and was set aside with every node under it. A function called by a program still records its step, and the tree still notes the entry's use when its condition holds.
- A program can ask the model at the point where only the model can judge: decide(question, show) waits for the model's <answer> and returns it, so what depends on how things are then is decided then, not written in advance. A <wait> now carries its check, a program that only reads (<wait>60<check>...</check></wait>): it runs when the wait ends and the model is told what it printed; a wait without a check is refused, and nothing in a check acts.
- An urgent event or the end of a unit no longer drops the reply the model is writing: it ends a wait and is told first with the next call, and the program in the reply runs, checking with expect what it relies on. Only a message of the user still sets the reply aside. A program written for half a minute was thrown away by the first event that came meanwhile.
- A reflex node with `over` that failed is tried again when its situation comes anew, also where its condition and its `over` never hold at the same time (hungry below one level, fed above another). It stayed failed for good: its `over` was asked only while its condition held.
- A conversation continued in a new process keeps the guide pages it was given: their names are saved with the conversation, and the new program process starts with them read. Before, every continuation refused the gated calls one page at a time until each page was read again.
- When the tree of reflexes acts is the model's to say. A node is started or not: `stop_reflex(names)` stops nodes (they stay in the tree and answer nothing) and `start_reflex(names)` starts them. The tree a library keeps comes into the tree not started when a session begins, where it used to act from the first moment: the model starts it with `start_reflex()` when the agent is where the tree is for. A line of `situations()` that only a node not started answers is not answered.
- The learning page tells a first time from a try again: the first time the agent comes to a step by doing the steps before it, and when it tries the step again it may put that same start back directly, with nothing the earlier steps did not leave. The skill that calls the learned skills in order is run from the start of the task.
- A program reads an entry of its library as the library holds it: `library.read(kind, name)` gives a skill's code and its test, or a note's text, so that it can fix the entry under its own name. The library's listing names each entry by its kind and name instead of a file inside the library.
- The model can take an entry out of its library: library.retire(kind, name, why), with the reason recorded in the index and the texts kept in the history. The learning pages tell it to keep one entry per subject and to correct or retire an entry that is wrong or out of date instead of adding another beside it.
- A node of the tree of reflexes is held to the pages of what it calls when it is set, not when it acts. set_reflex refuses a node whose functions call a skill call with an unread page, and hands the code they hold or name for the environment to the environment's own page check; a node set from the library when a conversation starts was checked when it was written. When a node acts nobody reads, and nothing waits for a page then.
- A node of the tree can say that its program uses no channel of the environment (`set_reflex(..., claims=[])`): it acts on nothing itself (it sets a fact, or a rule that other code reads), so it takes the environment from nobody, keeps no later node waiting, and runs beside everything for as long as its situation lasts.
- One program waits behind a running one, not a chain. While a program of the model runs, the model is still told to write and send the next one with after(unit), and now to send that one only; once one waits behind the running program, it is told instead to send nothing more behind it, to look in on the running one and prepare, and to change or cancel the waiting one if what the running one left no longer fits it. after(unit) refuses a unit that itself still waits.
- After a program whose checks all held but whose result was not there, the next program is refused while it states only those checks. A program that states a new check now lifts that refusal even when its new check does not hold and it acts on nothing: it has found what was not checked. A run found a stray item on the cursor that way, and the program that then cleared it was refused because its own checks were the old ones.
- The agent's prompts ask for three more things. A program is given about as much to do as the model needs time to write the next one, so that neither the agent stands while the model writes nor the model waits on a long program; every call says how long the last reply took to write and for how much of that no program of the model ran. In practice, a part counts as learned when a run of it ends with everything the next part needs, and what is kept is one skill for one goal, not the whole task as one skill. A node of the tree of reflexes compares the ways to answer its situation (keep out of its way, leave it behind, deal with it) by what each costs the task, and takes the cheapest.
- The model is told, with the pace of its last reply, how many times and how long it waited for programs of its own to end since its last program, so that it sees programs that are too long as it sees ones that are too short. The learning page says a way is learned when it worked from what the steps before it leave, with nothing added, run at the pace of any work.
- The model is not told the pace of its replies while the environment says the agent cannot act (its state has `can_act` false): nothing stands waiting for the model then. The same word of the environment is what keeps the tree of reflexes from being judged, now read from the state by default.
- The practice text has the agent take the parts it has not learned yet in order, where it said to go straight to the part not learned yet, and tells it to use its time wisely.
- The text around a practice task says what practice is for: to learn what the task needs; nothing in the run counts as the task, the task's rules do not bind it, and the agent goes straight to what it has not learned yet. The line "Practice from a better start than the task gives proves nothing" is gone.
- The watchdog that ends a reflex condition or controller at its deadline no longer stops the whole reflex tree. It raises the overrun in the caller's thread, where it lands at the next bytecode; when that was inside the watchdog's own bookkeeping, just after a lock was taken, the lock stayed held and every later reactive call waited on it for good (a run's reflexes all stopped and its programs hung behind a unit that never ended). The caller's side now takes no lock: arm and disarm are single dictionary operations, the watchdog is woken through a queue, and which side handles a due call is settled by removing it from the table.
- A node of the tree gives the environment back as soon as its situation is over: its program is ended there, its work done (set_reflex while_holds=True, the default; False keeps it running until it returns). A node whose condition stopped holding, or whom a fact told to stand aside, used to keep the environment until its program returned.
- The record says what a reflex node did not do: a node with a program notes when its situation comes and goes (rule holds, rule over), and, while it holds, why its program does not start (waiting: a node under it answers, its next turn has not come, another node runs before it), once for each reason. A run in which reflexes did not act had left no trace of why. A reflex's program no longer waits for a page to be read: a conversation that goes on in another process starts with no page read, and its reflexes failed at once with "read how routine is used first".
- The units of reflexes are no longer told to the model as its own programs. A reflex that ran was listed as "a program of yours", the hint to queue the next program named it, and the note that a program ended was left out while a reflex ran; the model watched and cancelled reflexes as if they were its work.
- `harness share` sends what an agent learned (a library) as a package to GitHub, another git remote, a website's folder or another computer, and prints the one line that installs it. Installing such a package gives a copy under `$HARNESS_HOME/libraries` that `--library NAME` uses and keeps learning in; a later install replaces it only while no run learned in it. `harness install` also takes a GitHub repository's address.
- The learning page asks for a skill for each thing to be done, sized so that one call of it is a program at the model's pace, and no longer for a skill that calls the others in order and is run from the start of the task.
- The system prompt stays as the conversation began: a library entry that comes into force, or a skill or an environment that joins or leaves, is told as a note with the model's next call. After a summary of the conversation the pages read are named in one line, not given again whole; the model reads one again with `guide(name)`. Both keep what the model has read the prefix its provider caches, and what stands after a summary small.
- A reflex whose condition reads the state is judged every period also while no program runs: the environment's state is read then too, as the environment changes by itself. It was read only while a program ran, so a node such as "come up for air" went unjudged while the model thought between programs.
- A run nobody talks to has the same turns as a conversation with a user. The model's answer ends its turn; while a program it started still runs, the run goes on and the program's end starts the next turn, and the run ends with an answer given when none runs any more. Before, the first answer ended the run and cancelled what was running. The run's limits (the model's calls, the wall time) cover all its turns. A reply in plain text is always the answer: a reply that only says what the model will do next is no longer sent back as a format error.
- An event told at once (priority `now`) no longer sets aside a call that is answering another event told at once: events of one urgency do not interrupt each other's answer, the later comes with the next call. A reflex node that tells each failure at once had failed, acted and failed again every few seconds, and each failure set aside the call answering the last one, so the model never answered while the body died. The node's own place in the queue had also overridden the rule that an event the call is already answering does not set it aside.
- While a program runs, the model is told first to write and send the program for what comes after it (with after()), and only then to look in on the running one: the agent goes on at once when a program ends instead of standing while the next one is written.

## 0.86.0

- A condition of a reflex that fails no longer removes its node and the nodes under it. One that raises does not hold that once and is judged again the next time; one that is too slow three times in a row stays in the tree and is not judged until the node is set again. The model is told what went wrong once for each reason, and the node's line says how often. A trial of a node whose condition raises says so in its result.
- What a reflex is and says for itself changes. Every node the model sets does something: `set_reflex` without `do=` is refused, a node above others has a program too (the fallback of its whole situation, for what no node under it answers or solves), and the name of an event is for watching what a program is for, not an answer to a situation. Each node says what the model hears of it: `tell=` ("never", "first" by default, or "later", "next", "now" for every time, at that place in the model's queue) for work done, and `tell_failed=` ("now" by default) for work that was not done and that nothing else took. A trial (`test=`) is no longer required, and a sentence in place of a trial is no longer accepted; instead a node's condition is judged once when it is set, and one that raises is refused. A tree proposed for the library is kept as its nodes stand in the tree. `runtime.reflex_trials` is now `runtime.reflex_method`. Two faults are fixed: a node that tells and ends what runs (`do="EVENT", ends=True`) no longer ends the answer of a node under it, and a node under another has done its work when its own condition or one above it no longer holds.
- A kept tree (`reactive` entry) may call `situations(...)` beside `set_reflex(...)`, so the list comes back with the nodes; a line its `covers=` names that the list does not have is left out when it is loaded. The refusal of a kept tree that calls something else names the line and the call, and the library's page states the rule with an example.
- What the model is told when its turn comes back with a program still running, and the core prompt with it, now say what a running program asks of it: know how long it has to run, do not wait for its end to learn that it failed, come back to look well before it is due to end, have its report show how far it is, and prepare what comes after it between the looks. Before, the message asked the model to follow the program two seconds after it started, when there was nothing to follow yet.
- A program is held to `expect(text, check)` where it acts, not where it starts: a call that acts on the environment is refused when the program has checked nothing before it, and a program that does not act (reading pages, keeping code, setting nodes) needs none. What a check itself does in the environment is reading; a reflex's program is held to nothing. The message the model gets while its program still runs now says the two things to do then: follow the program, and prepare what comes after it with what needs no acting on the environment. `after(unit)` waits until a unit has ended, however it ended: a program sent while another still runs begins with it, then checks with `expect`, then acts.
- The core prompt is less than half as long. It keeps what every reply needs: how to reply, how to work, and one line for each call. The details of the tree of reflexes (every setting of a node) and of units (waits, what the model is told and in what order, units of its own, who has the environment) are in two pages that a program reads on demand, `guide("tree")` and `guide("units")`. A page that was read is given again after a summary of the conversation. `reflex_method()` still works and returns `guide("tree")`. The other sections are brought to the same standard. The request for a reflection after an episode, the same whatever the agent acts in, asks for a note, a memory entry or a skill and no longer for a reactive helper: the nodes of a tree are kept from the tree the agent set. The library section gives `setup` in the signature of `library.propose` and no longer names a `tree` call. The checklist section has no example task. The section on world memory, which no setting could switch on and whose calls do not exist, is removed. The core names no kind of environment any more. Its default configuration has no table for a computer or a game and no table of prompts: a kind's package says its prompt and the agent's settings on it in its `kinds.toml` (`prompt`, `agent`), and may declare what is particular to the kind (`unnamed_in_lock`, `library_experience`, `record_waits`, `memory_report`, `interfaces`). Where nothing names a kind, it is `none`, a conversation with no environment, not a robot. What breaks: a `skill.toml` must say `embodiments` (the kinds it runs on, or `["*"]`); an embodiment file and a worker's profile must name their `kind`; `harness.embodiments.profile()` is gone (it built one kind's worker profile and is that kind's package's). `verify(claim)` is a call of every kind. The rest of what the core held of one package is that package's now. The session host and the command line name no workspace kind: a provider says where its kinds stand among those offered (`order` in `describe`), what it preselects (`preselected`), and a package adds its own flags to `harness run` (its host module's `run_arguments` and `run_sets`; `--vm-image` is the computer package's). `environment_kinds()` lists what a conversation can take, so no prompt lists kinds. A package brings the third-party sources it uses (`third_party/sources.toml` in the package); the core's list is empty. A service of a protocol that is not the core's (`http`, `openai_chat`, `mcp`) names it and gives that protocol's own table, read as `ServiceSpec.options` (it was `ServiceSpec.xpolicylab`). The guard actions `OPEN_GRIPPER` and `BACK_OFF` and the prompt feature `measured_gripper` are no longer the core's: the package of the kind that has them names them. The pins `environment/constraints.txt` of the core, which were one benchmark's, are gone: the browser benchmark's environment no longer names them (it is built anew on its next use). A prompt pack needs `pack.toml`: the section list for packs without one, which named skills of packages, is removed. Direct mode's action vocabulary (`runtime.actions`) is called with `skills`, the enabled skills, in place of `allow_policy`.
- `fetch` names itself as the-harness with its version instead of posing as a browser: sites that serve their pages to programs turned the earlier name away.
- The page on how a tree of reflexes is made says what a trial is for: a node has one plain goal (what is the case when its situation is over and stays over), its condition holds for as long as that is not so, its answer is written for the hardest form of the situation, and its trial checks the goal in one ordinary case. A node that reached its goal has passed; nothing is added to the goal afterwards. The whole tree is set first, each node with its one trial, before the nodes that did not pass are repaired.
- A program checks what it relies on before it acts: `expect(text, check)` runs `check` at once; it returns True, or what it found instead. When it does not hold, a program that acts ends there and the model is told what was found; a program that only reads goes on. A program without an `expect` is not started (where `runtime.purpose` is "required"). The end of a program lists every expectation with what its check showed, and says so when all of them held and the result is not there. The core prompt also says how to work: the plan becomes goals in order, each with a result that can be checked; while a program runs the model first follows it and then prepares what comes after; a problem of the same kind that comes back is answered by listing its possible causes. A node of the tree that acts at the wrong moment is changed in the tree, and `at_priority` is for rare cases. The page on the library says how to learn what the library does not hold and what counts as learned.
- The core prompt no longer says "When you know enough to act, act": it was read against planning the whole tree and checking what an action relies on before acting.
- The prompts say in one place what counts as tried, and everything else follows it: a thing is built for the hardest form of what it has to meet, it is tried in the least case that shows whether it does what it is for, and when it does it is done. The core prompt no longer asks for the hardest form to be tried first or for more trials the more a failure would cost; the instruction of a practice run no longer asks for everything to work more than once (only where the outcome depends on chance) and says that a node of the tree of reflexes is tried as the tree's page says. That page says to set every node that was laid out, each with its one trial, before coming back to any of them. A tree of reflexes that the agent proposes for its library takes no test: it is kept on the trials its nodes had when they were set, and nothing of it is run again; `library.propose("reactive", ...)` with a test is refused, and lines that set a node otherwise than it is in the tree are not kept.
- What a running program asks of the model is told with every call while one runs, in the same words: when the program has just been started, when a wait ended, when another program ended, when an event came. Before, only the call right after the start carried it; a model that came back to look was told the state and nothing else, and a program that ended beside the running one was followed by "the program ended, answer or write the rest".
- A skill can bring its own pages of instructions. Its `skill.toml` names them (`[guides.<name>]` with `file`, a path from the skill's folder), and the model reads one with `guide("<name>")`, as it reads the core's `tree` and `units`. A page may name the skill's functions that wait for it (`before`): such a function is refused until the page was read, and the refusal names the page. A page that was read is given again after a summary of the conversation.
- The core prompt says what the tree of reflexes is for: to act in time, because the model's reply takes seconds. A node's answer is an action that takes effect within the time its situation leaves; telling the model is for what no action is known for, or beside acting. A node that tells can end what runs too (`set_reflex(name, when, "EVENT", ends=True)`): the execution ends with that event. The model is told how many nodes of the tree only tell it, and the tree's line is left out of a turn when nothing in the tree changed and there is nothing of that kind to say.
- A node of the tree of reflexes is set together with its trial, and the method of designing a tree is read when the tree is made. `set_reflex(..., test=...)`: `test` is a function that brings the node's situation about (it is run at once and `set_reflex` returns what it showed: whether the node had its turn, how long that took, whether its program left the situation over) or a sentence saying why the situation cannot be brought about here; the node acts in either case. Before the first node of a run the model reads `reflex_method()`, the page on how a tree is designed and tried, which the core prompt no longer carries; `set_reflex` is refused until then, and the page is given again after a summary. The first time a node's program does its work outside its trial, the model is told what it did (`REFLEX_ACTED`). The tree's line says how many nodes were not tried or did not work in their trial. `runtime.reflex_trials = "optional"` turns this off. Breaking: `set_reflex` without `test` is refused unless that setting is `optional`; what a library entry sets is not affected.
- The guides say what a report is for instead of what its function takes: a node's `report` is the message read when the model is told of that node, written for that node's situation (what it will need then to judge whether the situation is over and to decide what to do next); a program's `until(report=)` likewise for that program. How the function is called is said after that. The sentence that named pictures as an addition to "the values that show the situation" is gone.
- What a node or a program reports of itself is a message, not a line of text: a report function returns text, plain data, a picture (what `look(...)` or `get_observation()` returned, or an image the program made), a file (a `pathlib.Path`: an image file is shown, a folder listed, any other file given as its text), or a list of these in the order wanted, with at most 2000 characters of text, 4 pictures and 4 files. A `look` inside a report belongs to that report alone. `look(camera, ...)` passes every setting it does not know on to the environment as given, so that an environment's views can take settings of their own (which stretch of time, how many frames); the environment's page says which. When a reflex takes the environment from another reflex's program, the model is no longer told that it chose to be told when it wrote that program.
- The model says what can happen to the agent during the whole task with `situations(...)`, one line for each, and each node names the lines it answers (`set_reflex(..., covers=[...])`); a line that needs no node is given with its reason. `set_reflex` is refused until the list was given, and a program that acts on the environment is refused while a line has nothing that answers it. After a program whose expectations all held and whose result was not there, the next program that acts is refused until it has an expectation the failed one did not have. A skill can say that an execution only reads (`reads=True`): it is held to no `expect`. A call refused because its page was not read now gives the page with the refusal. The core prompt keeps one list of goals; the page on the library no longer asks for a second list; the page on the tree says exactly when a node may begin again (`again_seconds`).
- The page on the tree of reflexes says how to choose what a node tells the model and what becomes of the work it interrupts by a question each: what the model would do with the news, and whether the interrupted work is still correct after the node's action. It no longer says to use the most urgent setting for dangerous events.
- The list of what can happen to the agent (`situations(...)`) counts for the values the environment's situation had when the list was given: once the state shows another, a program that acts is refused until the list is given again, and the refusal says to think the place through first. An environment can add a sentence of its own to every message that asks for the list (its profile: `situations_hint`), for example where its own description is to be read. The refusal of an action without an `expect` says that what holds for every action is not one; the message about expectations that all held names a wrong `until` as the other cause; the message for a program that still runs says to look at its result first when the next program depends on it.
- A node of the tree of reflexes and a program say for themselves what the model reads when it is told of them. A node that tells the model anything now needs `about=` (one sentence: the situation it answers) and `report=` (a function of the view and of what its program returned) and is refused without them; only a node with `tell="never"` and `tell_failed="never"` goes without. A program may give `until(condition, report=..., interrupted=...)`: `report` is told whenever the model hears of the program, and `interrupted` says what happens when a reflex takes the environment from it: `"tell"` (the default: it goes on and the model is told, three times for one program, the rest with its end), `"stop"` (it ends there) or `"never"`. The message about a reflex is now in words instead of a record: the node with its sentence, which program it took the environment from and how often, the node's report, and that program's own report.
- The core prompt and the refusal of an unchecked action now ask for one more kind of `expect`: what else the action changes besides the thing it acts on, and the state the agent is in when it is done, from which it has to be able to go on.
- The core prompt describes how to work as one loop, from what an action is for to what is observed of it, and the agent is told more at the moment it matters. A program has to say what it is for (`until(condition)`, or `until(None)` for one that only reads) or it is not started; `runtime.purpose = "optional"` turns that off. A reflex can end what its program interrupts instead of resuming it (`set_reflex(..., ends=True)`). An event is told with the how-manieth of its kind in the run it is; a running unit with which reflexes paused it and how often; the tree with how many nodes never had their turn. A wait with a time lasts that long (it was cut to `runtime.longest_wait_seconds`, which now applies only to a wait without a time). Everything told and replied is kept in `record.jsonl` in the run's directory, and the text that follows a compaction names it. The plan (`plan`, `step_done`) is shown to the model again when it has not touched it for ten calls. An environment can name the part of its state that is the agent's situation (`"situation"` in its profile): the model is told the first time it takes a new value. `review(code, purpose)` has a sub-agent that has not seen the conversation read code.

## 0.85.0

- Conversations read instruction files, as Codex and Claude Code do: yours, `~/.harness/AGENTS.md`, and the project's, from its root (the nearest folder with `.git`) down to the conversation's folder, one per directory: `AGENTS.override.md`, `AGENTS.md`, or `CLAUDE.md`, then that directory's `CLAUDE.local.md`. `@path` imports another file. Settings `instructions.load`, `.files`, `.root_markers`, `.max_bytes` (32768) and `.exclude` say what is read; `harness --bare` and `harness run --bare` read none.
- Any node of the tree of reflexes may have nodes under it. What a node does itself answers what is in its situation and in none of the nodes under it: they have their turn first, the node's own program or telling comes when none of them is answering, and gives way when one of them begins. So a node no longer has to be turned into a group before something can go under it: `set_reflex(..., under="name")` works under any node whose `when` is a condition, and that node is not set again. The core prompt says to write a node's condition by what is happening to the agent, not by its cause, and to put what is learned later under it.

- What the tree of reflexes cannot answer reaches the model. A node that tells (`do="NAME"`) now really tells the model: before, its event was recorded and never sent. A condition sees change: `view["was"]`, `view["unchanged"]` and `view["units"]`. A program's priority is held for one action: `with at_priority(n):` in place of `at_priority(n)`, which now holds nothing outside a `with` and says so; code that runs for long in an environment asks for one through its worker's state (`"priority"`). The core prompt says that the unexpected has two forms, what happens with no answer and what should happen and does not, and that the tree tells the model of both.
- The core prompt says how to design the tree of reflexes: from the top down, beginning with the widest situations and dividing each into the narrower ones; what several conditions have in common is judged once in the node above them; a deep tree is preferred to a wide one, because a node under another is judged only while that one's condition holds and a wide node still answers the case that was not listed; a new node goes under the narrowest node whose situation it falls in.

## 0.80.0 (unreleased)

A conversation's environment is no longer fixed by one saved setting, and its observation is no longer a fixed bundle per environment.

- **Each conversation chooses where it works.** The choice lists what the installed packages provide: no environment (conversation only: no worker, no view), a project folder, a background browser, background applications, your desktop, a separate display. `session.environment` is `ask` (the default: every new conversation asks, the last choice highlighted), `last`, or one kind. `computer.mode` is now the computer kind highlighted first; saved values keep working. The terminal has an opening choice and `/environment`, the app's composer has the two new choices, the command line takes `--workspace none|project|...`, and Python takes `workspace="none"`. Where nobody can be asked and the setting is `ask`, the task does not start and the error names the option.
- **One agent takes another environment when a step needs it.** `use_environment(kind, why)` attaches it to the same conversation and `release_environment(kind)` gives it back; its calls are under its name (`desktop.click(...)`, `project.run_command(...)`, `browser.read_page()`). `environments.attach` grades the permission (`never`, `ask_each`, `ask_once_session`, `allow`; default `ask_once_session`), with rules per kind. The question shows the model's reason. With `physical.level = "allow"` it does not ask; `never` still refuses; where nobody can be asked and the level asks, it is refused with the reason. Every attachment and its reason is in the conversation, the timeline and the trace. Real mouse and keyboard stay under the physical-input policy.
- **Sub-agents are off by default.** `session.agents`, `--agents`, `/agents`, the app's switch or `runtime={"agents": True}` turn them on, or the agent asks with `request_agents(why)` and you agree.
- **The model looks when it needs to.** Every turn is text. `look()` puts a view in the next turn with that program's result, `watch()` brings the views with every program (or every few seconds) until `unwatch()`, and a view stays for one reply unless the model keeps or pins it. A configuration that declares `runtime.cameras` keeps its standing watch unchanged: the resolved evaluation agent is byte-identical to 0.79.2 for its robot, desktop and game tables, and the robot packages are untouched.
- **Models that read no images.** Model entries record it (from the provider's catalog where it says; editable). Such a model is sent no image; `model.vision` names a model that describes a view for it; the environment choice says so beside environments with a screen.
- **The verifier** gets the state, the elements or page text the environment reports, and the views.

Checked on Windows with Python 3.14: 75 scoped tests over the changed contracts pass (environment choice 13, attaching and sub-agents 22, views and the model flag 17, first-use choices 14, workspace providers 7, model attribution 2); the docs type check, build (121 pages) and bundle budget pass.
